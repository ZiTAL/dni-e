# v0.2.2 — browser findings, cache fix and validation

Maintenance release. The shim code and its binary are unchanged; this release
updates the helper scripts, packaging and documentation with the results of the
post-renewal validation.

## What's new

- **Stale OpenSC cache fixed**: `scripts/verify-card.sh` clears the card cache
  before reading. OpenSC does not invalidate `~/.cache/opensc` when the DNIe
  certificates are renewed, so a board could keep showing the old (expired)
  certificates and IDs.
- **`scripts/test-tls-auth.sh`**:
  - encodes the CKA_ID as one `%XX` per byte (RFC 7512);
  - no longer depends on `p11tool` listings, which fail on OpenSC with GnuTLS
    3.8.9 on aarch64 (`Error in crt_list_import`);
  - no longer reports a false positive when GnuTLS says “Successfully sent”
    but the client sends an empty Certificate message.
- **Build scripts** exclude local `passwd`, `*.pin`, `firmado.pdf` and `*.sig0`
  from tarballs and Debian source packages.
- **Documentation**:
  - ARM64 board T10 (clean package install) and T9 (`C_Sign` with the
    authentication key);
  - PIN metadata caveat: the card reports an 8-character numeric PIN, but the
    valid PIN can be alphanumeric and longer;
  - Firefox/Chromium client-certificate findings.

## Browser findings

- **Chromium 155 + OpenSC works** for TLS client authentication when the
  server uses **TLS 1.2** and requests `RSA+SHA256` (PKCS#1 v1.5). The server
  receives and verifies the DNIe authentication certificate.
- **TLS 1.3 fails** with `ERR_SSL_CLIENT_AUTH_NO_COMMON_ALGORITHMS`: TLS 1.3
  requires RSA-PSS for RSA client certificates, while the DNIe/OpenSC key only
  provides `CKM_RSA_PKCS`.
  - Local workaround validated with Chromium 155:
    `chromium --ssl-version-max=tls1.2`.
  - This lowers the TLS version for all sites; use it only where the DNIe is
    required.
- **Firefox** lists the DNIe authentication certificate and asks for the PIN,
  but still sends an empty Certificate message against the same TLS 1.2
  server. Software certificates in the same profile are sent and verified, so
  this is a Firefox/NSS + OpenSC issue, not a card or PIN problem.
- The AEAT endpoint `www1.agenciatributaria.gob.es` requests a client
  certificate and includes `AC DNIE 004` in its CA list; Chromium offers the
  DNIe certificate. Completing the PIN dialog manually is required.

## Install

Debian/Ubuntu:

```bash
sudo apt-get install -y opensc p11-kit pcscd
sudo dpkg -i dnie-pkcs11-compat_0.2.2_arm64.deb
sudo apt-get -f install
```

Tarball:

```bash
sha256sum -c SHA256SUMS --ignore-missing
tar xzf dnie-pkcs11-compat-0.2.2-aarch64.tar.gz
cd dnie-pkcs11-compat-0.2.2-aarch64
sudo ./install.sh --binary --system
```

## Verified

- 21 shim tests on x86-64, aarch64 and riscv64 (unchanged shim).
- ARM64 board: T1–T6, T10 and T9 (authentication key) with the real card.
- Chromium + DNIe client authentication against a local TLS 1.2 server.
- Firefox + software client certificates against the same server.

## Known limitations

- Firefox does not send the DNIe client certificate (NSS/OpenSC).
- TLS 1.3 client authentication requires RSA-PSS, which the DNIe key does not
  provide; use TLS 1.2.
- Autofirma signing with the non-repudiation key needs a context-specific PIN
  and a graphical `pinentry`; on a headless board use VNC.
