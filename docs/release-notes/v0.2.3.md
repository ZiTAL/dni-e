# v0.2.3 — riscv64 Debian package and closed validation

Maintenance release. The shim source and binary are unchanged from v0.2.2;
this release publishes the riscv64 Debian package and records the final
validation results.

## What's new

- **riscv64 `.deb`**: the release workflow now assembles a Debian package for
  RISC-V from the cross-compiled shim (`packaging/debian/build-prebuilt.sh`)
  and publishes it with the tarballs and the amd64/arm64 packages.
- **Firefox client authentication**: validated with OpenSC, with the shim, with
  automatic selection and the chooser. Firefox requires the site to advertise
  the DNIe issuer (`AC DNIE 004`) in its acceptable CA list; otherwise NSS
  filters the certificate out and sends an empty list without asking for the
  PIN.
- **T7–T9 closed on x86-64, aarch64 and riscv64**; T8 (PAdES with Autofirma)
  and T9 (`C_Sign`, including the signing key) were reproduced on both boards.
- **Signing consent**: with the signing key, OpenSC's DNIe driver asks for user
  consent through pinentry (`CONFIRM`). Headless it fails as
  `CKR_FUNCTION_FAILED`; use a dedicated OpenSC config with
  `user_consent_enabled = false` for unattended signing. The card PIN is still
  required.
- **Documentation fixes**:
  - `pdfsig` 26.08 reports a false negative for the DNIe PAdES files; verify
    with `openssl cms`;
  - the OpenSC cache keeps the pre-renewal certificate IDs until
    `pkcs15-tool --clear-cache`;
  - the CA-list filter above, and the `-alias CertFirmaDigital` requirement
    for Autofirma's PKCS#11 store.

## Install

```bash
# Debian/Ubuntu, native package
sudo dpkg -i dnie-pkcs11-compat_0.2.3_riscv64.deb
sudo apt-get -f install

# Any Linux, release tarball
tar xzf dnie-pkcs11-compat-0.2.3-aarch64.tar.gz
cd dnie-pkcs11-compat-0.2.3-aarch64
sudo ./install.sh --binary --system
```

## Known limitations

- TLS 1.3 client authentication requires RSA-PSS; the DNIe key only provides
  `CKM_RSA_PKCS`. Use TLS 1.2.
- A server whose acceptable CA list does not include `AC DNIE 004` makes
  Firefox send an empty certificate list.
- jmulticard's `-store dni` needs a console for the PIN; use Autofirma with
  `-store pkcs11:…` on headless systems.
